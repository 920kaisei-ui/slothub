# 確率シミュレータ 実装仕様書

## 1. 目的

ブラウザ向けスロットゲームの宝石の出現確率、盤面、配当を調整するため、デフォルトで10万回転を一括試行できる軽量なCLIを作る。盤面生成・成立判定・配当計算・消去・落下・補充のロジックはブラウザ本編とCLIで共用し、同じ盤面と設定から同じ結果を得られるようにする。

## 2. ブラウザ本編の採用設定

本編は横6×縦7の42マスとする。[6×7プリセット](../../GemCrash/simulator/presets/6x7.json) を初期設定の基準とし、盤面生成から配当まで [共通エンジン](../../GemCrash/slot-engine.mjs) を利用する。

| 宝石 | 初期配置の重み | 補充の重み | 5個以上のかたまり1つあたりの基本配当 |
| --- | ---: | ---: | ---: |
| ルビー、サファイア、トパーズ、エメラルド | 各1 | 各1 | 各0.20倍 |
| ダイヤモンド | 1 | 1 | 0.60倍 |
| レインボーオーブ | 0.12 | 0.07 | 100倍 |

基本配当はワイルドを含む5個以上の成立で適用し、成立個数が増えても同額とする。第n連鎖では、その段階の基本配当合計にnを掛ける（`chainMultipliers: "linear"`）。

初期ワイルドは毎回1個または2個。2個目の出現率は設定で変更できるようにする。初期値は5.7%で、`wildCounts` に1個＝94.3、2個＝5.7を設定する。2個目の確率を `p`% に変更するときは、1個の重みを `100 - p`、2個の重みを `p` とする。

払い戻し率の調整目標は97.5%。同じ12シード・各570万回転で、2個目の出現率が5.7%の場合は97.28%、6%の場合は98.51%だった。5.7%設定では、連鎖なしは約39%、ちょうど8連鎖は約424回に1回、賭け額超えは約20%、4倍以上は約23回に1回だった。50回転ごとの収支中央値は賭け額1に対して−11.20、100倍の希少図柄の成立は1万回転あたり約2回だった。いずれも試行による実測値。希少枠をレインボーオーブへ移しても各図柄枠の重みと配当は同じ。

プロジェクトルートからの本編採用設定の試行コマンドは `node GemCrash/simulator/simulate.mjs GemCrash/simulator/presets/6x7.json`。設定ファイルを指定しない場合、CLIは比較用の横5×縦6設定（`GemCrash/simulator/config.json`）を読み込む。

## 3. 1回転のルール

1. **初期配置** — 新しい盤面を作る。初期ワイルド数を設定の重みで抽選し、最低1個をランダムに選んだ相異なるマスに置く。空きマスを設定された通常宝石から初期配置用の重みに従って埋める。
2. **成立判定** — 通常宝石の色ごとに、その色の宝石とワイルドを上下左右につないだ連結成分を探索する。通常宝石を1個以上含み、ワイルド込みで合計5個以上なら成立とする。必要個数は設定で変更できる。斜めだけの接触は対象外。同じ色の同じ連結成分は1回だけ数え、離れた連結成分は個別に判定する。複数色が同じワイルドを共有した場合も、成立した色ごとに配当する。
3. **配当と消去** — その段階で成立した各かたまりについて、色と成立個数に応じた配当を合算し、その段階の連鎖倍率を掛ける。成立判定をすべて終えてから、対象の通常宝石を一斉に消す。ワイルドは回転終了まで初期配置のマスに固定する。
4. **落下と補充** — 消去があった列だけ、ワイルドのマスを飛ばし、残った通常宝石の上下順を保ちながら列の下から詰める。空きマスを補充用の重みに従って通常宝石で埋め、成立判定に戻る。消去が発生しなければ回転終了とし、各段階の払い出しを合計する。連鎖数は消去が発生した段階数とし、消去なしを0、最初の消去を1とする。

## 4. 設定と異常時の処理

以下のデフォルト値は引数なしでCLIを実行する場合の設定。

| 設定項目 | 内容 |
| --- | --- |
| 盤面サイズ | 横幅と高さ。デフォルトは横5×縦6 |
| 通常宝石 | 種類と、初期配置用・補充用それぞれの出現重み。デフォルトは6種類 |
| 初期ワイルド数 | 個数ごとの抽選重み。デフォルトは1個＝88、2個＝12 |
| 成立条件 | ワイルド込みの必要個数。デフォルトは5個 |
| 配当 | 通常宝石の種類と、ワイルド込みの成立個数に応じた配当。デフォルトでは5個以上で、通常4種が各0.23014倍、サファイアが0.69042倍、ダイヤモンドが100倍 |
| 連鎖倍率 | デフォルトの `linear` では第n段階にn倍を適用する。段階別の倍率も配列で設定できる |
| 試行回数 | デフォルトは100,000回転 |
| 乱数シード | 同じ設定とシードで試行・集計結果を再現する |
| 連鎖上限 | 連鎖が終わらない設定による長時間実行を防ぐための上限 |

デフォルトのダイヤモンドは初期配置・補充とも重み0.035とし、他の5種類はそれぞれ重み1とする。ダイヤモンドの出現率は通常宝石を抽選する1マスあたり約0.695%。

- 実行前に設定を検証し、無効な項目と理由を示してエラー終了する。初期ワイルド数が1未満または盤面マス数を超える場合、負の重みがある場合、初期配置・補充・初期ワイルド数のいずれかの抽選で重みの合計がゼロの場合はエラーとする。
- 回転中に連鎖上限に達したら、使用した設定と回転番号（1始まり）を表示して中断する。打ち切った回転は通常の試行結果から除外する。

## 5. 集計出力

1回転の賭け額を1とし、割合の分母は完了した回転数とする。

- 平均払い出し倍率（払い出し合計 ÷ 完了した回転数）。
- 払い出しゼロ、0超1未満、元返し（1）、賭け額超え（1超）の件数と割合。
- 連鎖数ごとの分布。連鎖なし（0）も含める。
- 10倍以上、50倍以上、100倍以上の件数と割合。それぞれのしきい値を独立に集計する。
- 実行時間。

## 6. 実装方針

- 既存のJavaScript構成に合わせ、追加依存を最小限にする。
- 盤面は整数の1次元配列で保持し、上下左右の隣接マスを盤面サイズごとに事前計算する。
- 探索用の配列と消去フラグを使い回す。探索済みフラグは色ごとに管理し、成立判定がすべて終わってから盤面を更新する。
- 試行中は回転ごとのログや盤面履歴を保存せず、集計に必要な値だけを保持する。

## 7. 検証と実行報告

固定盤面で次を検証する。

1. L字につながった5個が成立する。
2. 斜めにだけ接する同色の宝石は成立しない。
3. 1個のワイルドを共有する複数色が同時に成立し、それぞれ配当される。
4. ワイルドの位置を固定したまま、通常宝石がそのマスを飛ばして落下する。補充後の再判定で次の消去が起き、連鎖数が増える。

固定盤面の検証後、デフォルト設定で実際に100,000回転を実行する。実行コマンド、設定ファイルと変更箇所、集計結果、実行時間を報告する。配当や出現重みを仮置きした場合は、使用した値を明記する。
